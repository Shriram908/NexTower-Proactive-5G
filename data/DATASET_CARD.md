# Synthetic corridor mobility, version 1

Owner and generator: Shriram Masalekar / HandoverAI. License: repository MIT license.

`corridor_mobility.csv` is generated by `synthetic_trace` from `configs/blocked_corridor.yaml`.
It contains 180 observations, one car, 0.5-second steps over [0, 90) seconds. The route is
850 meters long, speed is 10 m/s until the endpoint, then zero. Coordinates are local meters;
heading is radians counterclockwise from positive x. No GPS, identities, private or field data.

Recreate without overwriting the included file:

```sh
python -m handoverai export-trace --config configs/blocked_corridor.yaml --output /tmp/corridor-recreated.csv
diff data/corridor_mobility.csv /tmp/corridor-recreated.csv
```

Columns, in order: `time_s,vehicle_id,x_m,y_m,speed_mps,heading_rad`.
Rows are sorted by time and vehicle ID. Trace replay requires a contiguous prefix per configured
vehicle beginning at zero; permanent departure is supported, missing internal ticks/re-entry are rejected.
For external CSVs export coordinates in this same frame and match the configured tick grid.

This is a generated evaluation fixture, not a training dataset. The predictive policy is analytical;
no machine learning model or downloaded dataset is needed. Radio observations are generated separately
by the explicitly synthetic log-distance/blockage channel. A real mobility trace would improve mobility
realism but would not turn this channel into a calibrated 5G simulator.
